# 首版设计与数据约定

确认日期：2026-10-14。首版已按本设计实现，实际验证范围见 validation.md。

## 1. 产品边界与技术选择

通用岗位采集与筛选工具，提供本地 CLI 和 BOSS 单渠道。采用 Node.js 24+ 和 Patchright 1.60.2，参考已核对的 npe 独立模块；Node 内置 node:sqlite 的 DatabaseSync 保存批次与快照，JSONL 用于结构化回查，CSV 用于表格核对。依赖由 pnpm 锁文件固定，不依赖其他项目目录。

初期不建 Web 前端或 HTTP 控制服务；以显式命令和本地配置组织流程。首次真实采集由用户在专用浏览器会话完成登录。程序需要保存阶段性结果，允许结束后继续，不承诺无人值守运行。

## 2. 模块与拟定目录

| 模块 | 职责 | 拟定位置 |
| --- | --- | --- |
| CLI | 加载配置、启动阶段、输出进度 | `src/cli/` |
| 浏览器会话 | 启动专用 Profile，识别登录及验证状态 | `src/browser/` |
| BOSS 适配器 | 城市解析、搜索、滚动、列表响应映射、详情读取 | `src/platforms/boss/` |
| 数据处理 | 身份校验、字段规范化、薪资和经验分组 | `src/domain/` |
| 存储 | 批次、搜索来源、岗位与详情快照、检查点 | `src/storage/` |
| 导出 | JSONL、CSV、批次统计 | `src/export/` |
| 离线验证 | 脱敏接口样例与关键行为测试 | `test/` |

上游 BOSS index.js 混有联系相关 import，复用时需要抽取发现逻辑及必要依赖，不能整文件直接接入。详情读取独立实现；get_jobs 仅作字段与调用链参考，若后续实际复制代码先记录相应许可。

## 3. 身份、来源与快照

- 平台内岗位标识用 `(platform, platformJobId)`，职位对应的不同招聘者另存字段，不默认增加职位数量。
- 同一岗位由多个关键词发现：岗位去重，搜索来源全部保留。
- 列表快照与详情快照分别保存，使用批次 ID、岗位 ID 和内容摘要关联；旧正文不静默覆盖。
- 详情响应必须与当前目标岗位 ID 对应。无法确认身份的响应不得写成该岗位正文；导航跳转、过期或取不到正文分别记录状态。
- 详情读取优先保存页面正常操作产生的对应接口字段；有页面正文降级时记录来源。搜索标签或短摘要保持列表证据，不标作完整正文。
- 页面降级同时校验当前 URL、canonical 链接、标题和公司；只读取岗位介绍下的正文，不混入同样式的公司介绍。匿名公司无法核对时保留 missing。
- 不用字符长度单独判定“完整 JD”；应同时验证来源、岗位身份、正文存在及是否为摘要／异常提示，人工抽查完整性。

岗位记录至少包含：平台、岗位 ID、原链接、标题、公司、城市／区域、薪资原文、经验原文、学历原文、行业、规模、用工类型及依据、完整 JD、详情状态、列表／详情来源、采集时间、职位更新时间（可空）、招聘状态（可未知）。

搜索记录包含：批次、关键词、地区、平台筛选参数、实际搜索 URL、开始／结束时间、停止原因和发现关联。详情失败也保留列表数据。

登录 Profile、Cookie、完整请求头和安全令牌不进入岗位档案或日志；原始响应证据仅保存必要的岗位／公司字段，过滤与岗位调研无关的账号及会话数据。

## 4. 条件输入与筛选规则

城市、关键词和可选筛选项由本地配置输入，常用选项支持命令行覆盖，优先级为“命令行 > 指定配置 > 通用默认值”。每个批次保存最终生效条件，便于解释结果。条件缺失、格式错误和范围矛盾应明确提示，不根据开发者的个人偏好补齐。

城市和非空关键词是发起搜索的必要输入。薪资、学历、经验、行业、公司规模、用工类型和排除词等是可选条件，未设置时不限制相应维度。公共示例的空值表示未设置。

titleInclude 是标题包含词的 OR 条件，用于在宽关键词搜索之后排除同词异岗；它只检查职位标题，不能代替技能／职责评估。

搜索条件与结果筛选分开：平台原生筛选只承担可准确映射的部分，最终依据已保存字段执行统一规则。不支持的条件保留在本地筛选层，不宣称平台已执行。扩大搜索范围需要补采，调整已有字段上的筛选不必重新访问平台。

### 薪资

月薪筛选使用可选下限 L 和上限 U，单位为 K／月。首版采用区间重叠模式：职位区间与用户目标区间有交集即满足薪资条件；未设置的一端视为无界。上下限均未设置时不检查薪资，也不因缺薪资而增加该条件的待核实标记。

- 仅设下限 L：职位月薪上限大于等于 L 即存在交集；上限低于 L 则不满足。
- 仅设上限 U：职位月薪下限小于等于 U 即存在交集；下限高于 U 则不满足。
- 同时设置上下限：检查两区间相交，包括边界相等；L > U 是配置错误。
- 面议、缺失、年薪／日薪但换算条件不明或解析失败：待核实，不按 0 处理。
- 薪资发放月数另存；不通过年薪折算擅自声称月薪满足条件。区间相交不代表最终报价达到使用者期望。

### 用工与经验

用工类型支持 include（必须属于）、exclude（排除）和 prefer（优先排序）三类条件，未配置时均保留。仅凭公司名称或招聘者职位不能确认用工关系时标未知并给出线索，不用未知冒充企业直招。

经验、学历、行业和公司规模使用使用者配置的允许集合，空集合不限制；“经验不限”是实际岗位要求值，与“使用者未配置经验条件”区分。总开发经验和专项经验分别记录，学历和经验保留原文，不将求职者画像写进公共规则。首版不根据未经验证的个人技能给出录用概率。

排除词作用范围与命中字段需要可解释，缺失字段遵循 unknownPolicy。初版未知条件结果放入待核实组，已确认不满足与待核实分开；偏好只影响排序或标签，不作为硬性淘汰条件。分类采用“符合已设条件／明确不符合／待核实”，并附维度标签。

筛选为可重新执行的派生结果，保存配置版本和理由；不改变原始岗位证据。

## 5. 运行、恢复与导出

详情顺序处理，间隔和批次上限可配置。每完成一条就保存结果；中断后可恢复尚未处理的岗位。登录失效、平台验证时暂停，不循环刷新或持续重试；单岗超时记录失败，有限重试须区别于登录／验证故障。

跨次批次不会把历史“正文已取得”自动认作当前仍在招；刷新策略和正文更新时间明确记录。

导出支持符合已设条件、明确不符合、待核实及各维度标签，保留对应配置版本与依据。维度标签可以重叠，批次总数以岗位去重数为准。JSONL 保留结构信息，CSV 使用 UTF-8 BOM、正确转义多行 JD，并处理表格公式注入；批次摘要报告发现、去重、详情尝试、正文成功、失败和筛选分布。CSV 可简化展示字段，完整证据保留在 JSONL／本地存储。
