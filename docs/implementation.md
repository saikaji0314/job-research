# 实施顺序与验收

本文件记录首版工程计划与验收标准。项目按可公开发布的通用工具维护；2026-10-14 已完成三个阶段的首版实现及一次真实小批回归，具体范围见 validation.md。

## 阶段 1：列表采集

状态：已实现并验证真实登录、多关键词搜索和去重；增量滚动及停滞停止由离线样例覆盖，本次真实小批因各词预算较小，没有触发翻页／滚动。

1. 建立 Node 包、CLI、通用配置校验与只读动作集合，记录实际依赖版本；搜索条件由输入指定，不内置任何求职者画像。
2. 抽取 npe 中必要的城市、搜索、列表响应和滚动逻辑，保留许可与固定 SHA 来源；排除联系模块。
3. 建立本地浏览器会话和用户登录入口，登录／验证状态无法确认时暂停。
4. 接入 SQLite，保存搜索批次、原始列表证据、关键词来源和去重岗位。

验收：离线样例验证字段映射、多词去重、增量发现和停止条件；用户登录后做一次真实搜索及一次滚动，逐项记录结果，不用模拟测试替代真实验证。

## 阶段 2：完整 JD 与恢复

状态：已实现接口与经身份核验的 HTML 正文两条路径、快照和继续命令。真实批次 30 条中 26 条取得正文，4 条保留缺失状态；暂停、失败重试和中断边界由自动测试覆盖，真实页面缺正文重试已执行。

1. 逐岗访问详情，读取与目标岗位身份一致的正文及公司、经验、学历等字段。
2. 校验响应岗位 ID，分别记录完整正文、摘要、超时、身份不符、失效及验证状态。
3. 每条保存详情快照与检查点；提供失败／待处理清单及继续执行入口。

验收：模拟串岗、缺字段、登录失效和中断，确认不会保存错误正文；真实批次尝试 20～30 条线索，报告完整正文获取率及失败原因。人工抽查至少 5 条与原页面一致。

## 阶段 3：分组与研究导出

状态：已实现配置筛选、标题包含词、薪资区间、允许集合、用工标签、排除词和三种导出。真实批次已导出，5 条正文页面核对完成；规则符合不等于候选人能力匹配。

1. 实现可配置薪资范围、经验、学历、行业、公司规模、用工类型和排除词的筛选，区分硬条件与偏好。
2. 导出 JSONL、CSV 和批次摘要，保留原文、来源、时间、未知状态及筛选理由。
3. 复查采集范围和筛选结果质量，决定是否扩大批次及接入第二渠道。

验收：薪资上下限、未配置条件、区间边界和未知口径正确处理；偏好不误作排除条件；用工等分类可追溯；相同数据更换条件可重新筛选；导出中多行文本可回读且公式前缀得到处理；跨关键词岗位总数与来源关系一致。测试使用虚构或脱敏样例。

## 当前完成与下一步

- 已完成：CLI、依赖锁定、列表与详情采集、本地快照、继续采集、通用与资格筛选、四组 CSV 和审计全集导出、32 项自动测试、真实 30 条采集与 5 条抽查。
- 已知缺口：匿名公司等特殊页面的身份字段不足；用工类型识别较保守；真实滚动、更多平台和其他运行环境尚待回归。
- 下一步：根据真实缺失样本完善适配，在需要扩大采集范围时验证真实滚动；新增平台前保留首版回归样例。

真实验证时由用户完成平台扫码或验证。具体验证码出现前无需为实现代码额外等待用户操作。
